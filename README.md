# BladeAccelerations

Wind-tunnel experiments on a 3D-printed (Formlabs Rigid 4000) model of the
DTU 10-MW blade, 0.28 m span. A motor turns the blade through a sweep of
angles in a pressurized wind tunnel. At each angle, four accelerometers along
the span (S1 at the root to S4 at the tip) and a six-axis load cell at the
root record 60 s of data. The goal is to map where in the flow the blade
vibrates, and why.

This repository holds the acquisition code that runs on the lab PC, the
post-processing pipeline, and the analysis reports.

## Getting started

```bash
poetry install                                          # Python 3.12-3.13
poetry run python -m unittest discover -s scripts/aquire_data/tests   # 34 tests
```

The data are not in git (`.gitignore`). Put them under `data/`:

| folder | contents |
|---|---|
| `data/Production_10-8-26/<run>/` | Raw production runs, 6-15 Oct 2026, 32 runs: `angle_*deg.csv` (accelerometers), `angle_*deg_load.csv` (load cell), `encoder_log.txt`, `coordinate_frame_angles.csv`, `run_metadata.json`, `tunnel_conditions_summary.csv` |
| `data/Production_summaries/` | Generated by `extract_run_summary.py`: per-run `angle_summary.csv`, `spectra.npz` and `run_info.json`, plus `master_*.csv` tables |
| `data/DTU10MW_rigid4k_ringdown*/` | Ring-down (tip-flick) tests, with and without the mount bolt |

Without the data, the transform tests still run. The data tests in
`test_angle_chain.py` are skipped.

## Layout

```
scripts/aquire_data/       acquisition (lab PC) and post-processing; see its README.md
  utils/                   shared modules: coordinate transforms, run loader, live plots
  tests/                   tests and the rig / turbine renderings
scripts/data_analysis/     spectral tools (accel_spectra.py), ring-down and experiment analysis
scripts/flash/, fw/        accelerometer-board firmware and flashing tool
reports/<topic>/           one folder per analysis: <name>.tex, <name>.pdf, make_figures.py, figs/
figures/                   generated plot outputs (figures/psd_analysis/ is not tracked)
user guide/                accelerometer board (AF10R1) manual and wiring notes
```

## Pipeline

1. **Acquire** (lab PC): `scripts/aquire_data/main.py` runs one sweep at fixed
   tunnel conditions and writes a run folder.
2. **Summarize**: `extract_run_summary.py` reads each run once and writes
   per-angle metrics, spectra and flow angles to `data/Production_summaries/`.
   It reads one run at a time, run from `scripts/aquire_data/`:

   ```bash
   python extract_run_summary.py --root ../../data/Production_10-8-26 \
       --out ../../data/Production_summaries
   ```
3. **Plot**: `plot_angle_sweep.py`, `plot_psd.py`, `plot_design_space.py`,
   `angle_metrics.py` and others. These read only the summaries.
4. **Report**: each `reports/<topic>/make_figures.py` makes that report's
   figures and prints the numbers quoted in it. Build the PDF with
   `latexmk -pdf`.

## Things to know before using the data

- **Accelerometer timing.** The sensors run at **1493 Hz**, not the
  configured 1600 Hz, and about 16 % of samples are lost between reads (84
  samples on, about 16 off). `scripts/data_analysis/accel_spectra.py` places
  the samples on the true time grid and masks the gaps. Treating the samples
  as evenly spaced puts every frequency about 22 % low. Each strong peak also
  has weak copies (about 3 % of its power) at ±14.4 Hz. See
  `reports/accel_sampling`, `reports/pcb_manual_notes` and
  `reports/accel_postmortem`.
- **Flow angles.** The motor angle maps to the blade's inclination and angle
  of attack through `scripts/aquire_data/utils/coordinate_transforms.py`. The
  version of 1 Oct 2026 was wrong: it flipped every inclination and shifted
  every angle of attack by 78.2°. It was fixed on 12 Nov 2026. **Summaries
  written before that date have wrong `aoa_deg` and `inclination_deg`.**
  Regenerate them. For simulations, use `reports/angle_check/angle_mapping.md`.
- **Ring-down modes.** Without the mount bolt, which is how the production runs
  most likely ran, the blade has its first flapwise mode at 55 Hz and a first
  edgewise / second flapwise pair at 131 and 138 Hz. The 85 Hz peak is most
  likely a mode of the mount, not of the blade. See `reports/ringdown`.
